A software interface that hides complicated internal work behind a small set of actions is called an abstraction, or more specifically, an interface or API when it defines how other software interacts with a system. Its purpose is to simplify use by exposing only the essential operations while concealing implementation details such as algorithms, data storage, communication protocols, and error-handling mechanisms. This separation allows developers to work with a clear, stable set of commands without needing to understand or manage the system’s internal complexity. For example, a payment API may provide actions such as charge, refund, and check status, while hiding encryption, bank communication, fraud checks, and transaction recording. Abstraction improves productivity, reduces mistakes, and makes software easier to test, maintain, and replace. Internal components can be optimized or redesigned without requiring changes from users who rely on the interface. In this way, the interface acts as a contract: users provide valid inputs, invoke supported actions, and receive predictable results, while the system remains responsible for carrying out the difficult underlying work.
