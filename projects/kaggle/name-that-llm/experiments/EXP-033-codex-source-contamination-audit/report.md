# EXP-033 · Codex原文与官方、公共数据的提示词污染诊断

**结论：1000条原文中未检出明确的内置指令、工具或环境文本混入；但存在明显格式分布偏移。公共来源的单段要求、后处理、筛选和不同题型提供了明确混杂证据，无法将偏移单独归因于Codex内置提示词，也不能证明不存在间接影响。**

检查已采集的1000条Codex回答、官方全部2699条，以及7个固定公共来源的9张回答表；定量主对照只取Luna/Terra/Sol/Astra四标签。raw、clean、matched、pool互有重叠，分别展示，不把行数相加当作独立样本。官方匹配四类共600条，每类150；Codex每类250。

本次仅进行本地描述统计、逐条文件/事件核验和候选人工复核。没有生成新回答、训练分类器、计算OOF或提交比赛，未修改原始数据。

## 直接文本污染：未发现明确证据

- 1000/1000回答与原始final文件、agent_message及所存哈希一致，每条恰有一次完成事件。
- Codex/AGENTS/技能与记忆文件、开发者或系统指令字段、角色分隔符、工具命名空间、真实工作区路径、AI身份自述、最小基础指令回声等强筛查命中0条；工具事件和整段prompt回声0条。
- 7条弱候选经人工检查均为正常房间说明或邮件措辞；另6条末尾“let me know if”等均是用户要求的邮件正文，不是助理附加邀请。没有据此改写或剔除原文。
- 原事件包含2000个已知CLI功能提示，均未进入回答。不能把它们当作2000次生成失败或回答污染。

筛查不能覆盖所有潜在泄露形式。全量文件与规则扫描覆盖1000条；人工语义复核覆盖命中候选，不代表1000篇逐句事实验收。[直接检查与规则](metrics/direct-traces.json) · [人工复核](metrics/direct-traces-review.md) · [末尾邀请语复核](metrics/closing-offers-review.json)。

## 为什么这不是内置提示词污染的因果证据

1. **官方缺少原始请求。** 只有id/prompt_id/text/model，不能证明其原生输出就是单段，也不能确定是否进行过处理。
2. **公共来源主动约束格式。** Prvs-new和Lucas均明确要求单段、无标题/列表；Lucas只有首尾strip，但仍受生成指令约束。Enai实际9719条请求全部命中单段/纯散文格式要求，其中5408条还使用要求single paragraph的system；Codex250条题目没有同等格式限制。Enai gap/new分别报告，避免混用有system与无system的请求。
3. **处理/筛选进一步改变分布。** Abdullah/Dophuchung折叠全部空白；prvs clean是筛掉多段/多数Markdown的子集，4926条文字与raw逐字一致，并非修改原文。matched/pool为重叠汇总视图；保存数据卡声明按标签过滤整段回答，不能据此声称直接删掉标点。
4. **更多换行不是Codex独有。** 已有20对同题同请求模型对照中，Kaggle和Codex都是13/20含换行，且逐对一致；加粗为1/20对6/20，仍值得继续观察。这里只有10个独立题组、每路每单元一次生成，尚不能区分随机波动与稳定渠道效应。

## 输入环境与仍未排除的问题

最小基础指令与部分禁用开关没有建立“裸API等价性”。在20对中，Codex报告输入token分别固定多Luna2543、Terra4078；可能涉及固定上下文或计数差异，不能把差值当作隐藏提示词的准确长度。

早期debug prompt-input显示额外上下文，但该debug不能使用真实exec的ignore-user-config路径，不能据此声称这就是1000次实际完整请求。实际事件未公开完整服务器输入，全部1000条仍为requested_only标签。没有直接泄露不等于已经排除间接语气/措辞/组织影响。

## 数据使用判断与下一步

- 保留1000条原文和来源标签；没有发现需要因明确指令泄露而立即剔除的回答。
- 暂不把它们当作与官方/公共同分布的可直接混合数据。分类器可能利用来源特有的格式；本次没有训练，不能宣称发生了这种学习或已经损害分数。
- 若继续采样，应另建受控小实验：相同题目、请求模型、reasoning和明确格式约束，在两路做重复生成，比较渠道内与跨渠道波动。不要覆盖现有250题或重写已保存原文。
- 若后续验证训练收益，保留原文并另建派生格式视图，在固定prompt分组上对比原文与共同格式处理；该步骤尚未执行，不能把去掉Markdown视作去除了所有内置影响。
