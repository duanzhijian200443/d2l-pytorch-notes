## 2. 记录口径与比赛约束

### 2.1 每条结论必须注明证据类型

- **作者报告**：来自公开 Notebook 的说明、标题或作者实验表，尚未由我们独立复现。
- **源码核对**：确认代码、参数或附件版本之间的关系；不能直接推出分数或耗时。
- **本地测试**：包括小样本计算、静态检查与模拟生命周期测试。
- **公开样例验证**：在实际云端运行公开测试样例，核查预测和产物。
- **正式 Public LB**：以自己的 Kaggle 提交 ID、终态和实际分数为准。
- **待确认**：缺少日志、无法确定原因或尚未跑完；不要补成成功/失败结论。

### 2.2 当前比赛事实

2026-10-29 通过 Kaggle MCP 读取官方 Data、Evaluation、Code Requirements；同时读取本地 CSV 核对：

- 任务：对每段文本预测 18 个候选模型中的一个。指标为 **Balanced Accuracy**，即 18 类召回率的平均值。
- 官方训练集：`2699` 条文本、`150` 个 `prompt_id`、`18` 类。隐藏测试的 prompt 不出现在训练集。
- 当前本地公开 `test.csv` 有 **3 条**；隐藏重跑约 **4000 条**。官方 Evaluation 的一段说明仍写“单条示例”，实际数量以文件和较具体的 Data 页面为准，代码不要硬编码行数。
- Public / Private 的类别比例不同；公开榜提高不能保证最终隐藏榜提高。
- 正式提交通过 Kaggle Notebook 重跑，关闭互联网；CPU/GPU 运行上限均为 **9 小时**；输出为 `submission.parquet`，列为 `id, model`。

### 3.1 这类方案到底在做什么

可以把它理解为多个“文本鉴定员”联合判断作者：

1. **大型鉴定员**：Qwen、Llama 等骨干加载已经训练好的 LoRA 和分类头，把文本变成风格特征，然后输出 18 类分数。这些骨干不是比赛要识别的那 18 个目标模型的逐一复制品。
2. **便宜的鉴定员**：字符/词 n-gram、功能词、标点形状、文本变形等分类器，捕捉写作习惯。
3. **削弱题目影响**：相同题目会让不同模型的回答看起来相似；prompt 分组、中心化特征和 Gaussian 模块尝试分离“说什么”和“谁在说”。
4. **疑难复核 ATLAS**：对集成不确定的文本再计算来源条件似然，作为额外证据。
5. **结果融合与修正**：综合不同鉴定员的分数，再做类别比例平衡、家族内修正或文字格式修正。

运行这些推理 Notebook 不等于从零训练大模型：主要是加载公共适配器/分类头、计算特征和预测，部分 CPU 分类器会现场拟合。重新训练全部 LoRA 是另一种资源预算。

## 5. 异常与排查经验

| 现象 | 已知原因/证据 | 以后应怎么判断 |
|---|---|---|
| Kaggle OAuth 返回 `ClientId too small: codex` | 历史浏览器报错，认证请求中的 client ID 被拒绝 | 认证尚未成功；不要把重试打开页面当作已连通。后续 MCP/CLI 访问已在其他步骤实际使用成功 |
| 127.0.0.1 拒绝连接 | 历史认证回调页现象，截图不足以确定具体原因 | 检查授权发起进程是否仍监听；不凭截图断言账号或 Kaggle 服务异常 |
| Colab reCAPTCHA / Drive 授权阻塞 | 用户手动完成验证/授权后继续 | 记录为准备阻塞，和模型计算时间分开；避免 GPU 空等 |
| Colab CLI `drivemount` 交互挂起 | 既有流程发现交互需要可用 TTY | 使用支持 `/dev/tty` 的交互会话；重复登录前先确认旧执行是否仍在等待 |

| `UNEXPECTED` 权重告警 | 截断模型层数时可出现未使用权重，原流程也有类似输出 | 告警本身不证明失败；核对结构、必要权重、锚点/训练样例一致性及后续日志 |
| GPU 强很多，总时长却没明显降低 | CPU 分类器拟合、文件读取、加载和数据拷贝也占时间 | 分阶段计时；不能把全部时长按理论 GPU 性能倍数相除 |
| 状态 JSON 仍写 RUNNING，但 VM 已消失 | E06 的云端状态文件停止更新 | 状态文件必须带更新时间；结合后台实际会话判断，不能只看一个字符串 |
| 提交等待超过七小时 | V30 最终成功得到 0.654；当时没有隐藏阶段日志 | 等待长不等于失败，也不能保证成功；队列、评测、终态分别记录 |

## 6. 时间、费用与缓存：哪些数值不能混用

- V30 的 **3:38:39** 是公开样例完整运行；不是正式隐藏评测时间，也不是纯 GPU 计算时间。
- E06 的 A100 只运行到中断，没有完整总耗时。此前讨论的 **1.5～2.5 小时、约 2 小时**只是条件性估计，不是实测结论；T4 上的 V30 与 A100 上的 V32 也不是严格同版本对照。
- 已缓存权重减少重新下载；阶段断点减少已完成计算的重做。这是两种不同的节省。
- 新机器仍有挂载、安装、磁盘拷贝和模型加载成本；修改代码/输入/环境可能使旧计算断点失效。
- 目前没有完整、可核验的单次 CCU 消耗记录，不补造费用数字。后续记录开始/结束余额、资源费率、实际占用时间，以及是否有其他并行会话。
- 单次 Colab 实验的四小时保护是我们设置的资源上限；Kaggle 正式评测九小时是比赛限制，两者不能互相替代。
